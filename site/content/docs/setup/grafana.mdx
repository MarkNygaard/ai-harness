---
title: "Grafana"
description: "Connect Grafana once, read-only, so workflow scripts and the chat can query Prometheus metrics, Loki logs and dashboards without ever holding the token."
---

With Grafana connected, the harness can read your own data: traffic, latency,
error rates, logs, or what a dashboard shows. A workflow's `bash` or `script`
steps query it with
[`harness grafana`](/docs/operating/cli#harness-grafana), and the chat
queries it with its own tools.

Connect it on **Settings → Integrations → Grafana**.

Grafana is an **integration**: the harness holds the token and makes each read
itself, and nothing it starts ever gets the token. If you also want agent
steps to use Grafana's own MCP server as tools, add it under
[MCP servers](/docs/setup/mcp-servers#sentry-and-grafana-as-mcp-servers).
That's a separate setup.

## The token

In Grafana, go to **Administration → Users and access → Service accounts**.
Add a service account with the **Viewer** role, and create a token for it. It
starts with `glsa_`.

Give it Viewer, nothing more. The harness only lets reads through, and a Viewer
token makes that hold even if something changes upstream.

Also enter the **Grafana URL** the harness reaches it at. It has to be
reachable from where the harness runs.

## What can be read

Only reads:

- **Datasources:** the list, and one by name or uid.
- **Loki and Prometheus,** through Grafana's datasource proxy: queries
  (instant and range), label names and values, series, Loki patterns and
  index stats, Prometheus metadata.
- **Dashboards:** search, and one dashboard by uid.

Anything else is refused.

## From a workflow

For queries that should run the same way every time, such as a weekly
report's numbers, a [`grafana:` step](/docs/workflows/authoring#node-bodies)
is cheaper and steadier than an agent. Its output is the JSON answer, for later
steps:

```yaml
- id: lines
  grafana:
    loki: 'sum by (job) (count_over_time({app="web"} [1d]))'
    start: now-7d
    step: 1d
```

A script that makes many queries, or works on the answers, uses
[`harness grafana`](/docs/operating/cli#harness-grafana) instead, or calls the
proxy directly with the run's own grant.

## In the chat

The chat can query Grafana for questions like "what did checkout latency look
like yesterday?" It's told to find the datasource and label names before
querying, to keep time ranges tight, and to show the query it ran so you can
check what it found.
