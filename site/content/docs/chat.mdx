---
title: "Chat"
description: "Ask the harness about runs, pull requests and Linear from inside the dashboard, or build a workflow with it."
---

Every page of the dashboard has an **Ask** button in its header. It opens a
chat with an agent that can use the harness's own tools, the same ones the
[MCP endpoint](/docs/mcp) offers. You don't need an editor or an MCP setup.

For a longer conversation, **Chat** in the sidebar opens the same
conversations on a page of their own, and the panel's expand button takes you
there. Like any sidebar entry, you can hide it under **Settings →
Preferences**.

## What to ask

- **Why a run failed**, or what a running one is doing. Open the run first and
  the chat knows which one you mean.
- **Which pull request to test.** When a run fails after opening its PR and a
  rerun opens another, ask "which PR should I test for ECOM-44?" The chat looks
  up every run for the issue, checks each PR on GitHub, recommends one, and
  links its preview deployment.
- **Why a Linear issue didn't start.** It checks how your columns and bindings
  connect.
- **Build or change a workflow.** It reads the node catalog, validates before
  saving, and saving keeps the previous version. If you have the workflow open
  in the editor, the chat knows which one you mean.

## Questions about code

A new conversation can read one project's code: choose it under **Read code
from** before your first message. The chat
gets a read-only copy of the project's base branch (every repo, for a
multi-repo project) and can search and read files in it, but not change them.
To have code changed, start a run.

The copy is taken when the conversation starts, and the conversation keeps
reading that same commit even after the branch moves on. Start a new
conversation to read newer code. Conversations at the same commit share one
copy, and copies nobody has read for a day are removed.

With Claude Code, the agent reads with its own tools, which refuse anything
outside the copy. Pi's own file tools can't be limited that way, so Pi chats
never get them. Instead, the harness loads its own Pi extension, which gives Pi
file tools that check every path and refuse anything outside the copy.

## What it can't do

The chat cannot run commands, change files, or browse the web, and it can only
read files in a code conversation's own checkout. This is enforced by the
agent's command line and, for Pi, by the harness's extension, not just
requested in the agent's instructions. Settings from the project's own
repository (`.claude/settings.json`) are never loaded, since they can define
commands to run, and a Pi chat loads no extension but the harness's own.

**Starting a run or deleting something waits for you.** When the agent asks
to start a run, start an A/B pair, delete a workflow or uninstall one from the
library, a card appears in the chat with **Confirm** and **Cancel**. Nothing
runs until you press Confirm. The server enforces this, whichever model is
answering.

What the chat does is recorded as yours. A run it starts and a workflow it
edits show you as the person behind them, marked "from chat".

## Choosing the agent

An administrator picks the agent under **Settings → Chat**. The options are
Claude Code, and Pi with a Kimi or ChatGPT login. Only agents that can be
limited to the harness's tools are offered, and only once they're connected
under **Settings → Agents**. With nothing chosen, the chat uses Claude Code if
it's connected, then Pi.

A change applies to new conversations. A conversation stays on the agent it
started with, because one agent can't resume another's session.

## Privacy

Conversations belong to whoever started them, and nobody else sees them in
their list. Delete one from the history menu in the panel.
